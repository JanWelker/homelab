# Known Limitations

Things this cluster does not do. None is a bug; each is an accepted tradeoff or work not yet done.

| Limitation | Consequence | Mitigation / plan | Where documented |
| --- | --- | --- | --- |
| **The API endpoint address is fixed at `kubeadm init`** | The kube-vip VIP is baked into the API server certificates, every kubeconfig and Cilium's `k8sServiceHost`; moving it touches every node | Choose it once, outside any DHCP range and the LoadBalancer pools; the next build [uses a name](<https://homelab.wlkr.ch/operations/control-plane-vip/index.md#endpoint-name>) | [Choosing the address](<https://homelab.wlkr.ch/operations/control-plane-vip/index.md#choosing-the-address>), [migrating in place](<https://homelab.wlkr.ch/operations/control-plane-vip/index.md#in-place>) |
| **OpenBao needs an operator to unseal it** | Every restart seals it until the [threshold of key shares](<https://homelab.wlkr.ch/platform/openbao/index.md#at-a-glance>) is supplied; sealed, no `ExternalSecret` resolves and certificates silently stop renewing | Check `bao status` after reboots; auto-unseal would add an external dependency | [Unsealing after a restart](<https://homelab.wlkr.ch/platform/openbao/index.md#unsealing-after-a-restart>), [after any node reboot](<https://homelab.wlkr.ch/operations/nodes/index.md#after-any-node-reboot-unseal-openbao>) |
| **One operator holds every credential** | The unseal key shares and `output/credentials/` sit with one person, on the deployment host | Copy them to a password manager | [Bootstrap](<https://homelab.wlkr.ch/platform/openbao/index.md#bootstrap>), [Repository layout](<https://homelab.wlkr.ch/architecture/index.md#repository-layout>) |
| **Alerting reaches one mailbox** | A rejected mail, an expired SMTP password or a Ceph outage ([Prometheus and Alertmanager](<https://homelab.wlkr.ch/platform/monitoring/index.md#at-a-glance>) sit on Ceph) stops alerts silently; `Watchdog` proves only as far as Alertmanager | An off-cluster `Watchdog` mail check; meanwhile, the routine health check | [Alerting](<https://homelab.wlkr.ch/platform/monitoring/index.md#alerting>), [routine health check](<https://homelab.wlkr.ch/operations/index.md#routine-health-check>) |
| **Automatic updates stop at patch releases** | Nodes follow the Kubernetes minor they were built with; a minor upgrade is manual | By design | [Nodes are pinned to a minor series](<https://homelab.wlkr.ch/operations/upgrades/index.md#nodes-are-pinned-to-a-minor-series>), [upgrading a minor deliberately](<https://homelab.wlkr.ch/operations/upgrades/index.md#upgrading-a-minor-version-deliberately>), [Kured](<https://homelab.wlkr.ch/platform/kured/index.md>) |
| **The `infra` AppProject is permissive** | The `infra` AppProject allows every kind in every namespace, so a platform `application.yaml` can deploy anything anywhere | Narrow the projects | [Security Posture](<https://homelab.wlkr.ch/architecture/security/index.md#authorization>) |
| **Reprovisioning needs the boot server on the segment** | Rebuilding a node needs `make serve` on the nodes' L2 segment, the DHCP pointing at it and a power cycle; there is no remote rebuild | A running node reboots and rejoins without it | [Boot & Bootstrap Process](<https://homelab.wlkr.ch/architecture/boot-process/index.md#every-boot-after-the-first>) |
| **The object store survives one host down, no more** | During every Kured reboot the RGW data pool, which holds the backups and Loki chunks, has no redundancy left, while `rbd-pool` still has some | Accepted: a pool's erasure profile is fixed, so fixing it means a new pool and moving every bucket | [Object storage](<https://homelab.wlkr.ch/platform/rook-ceph/index.md#object-storage>) |
| **Cluster admin is a client certificate, not OIDC** | `output/kubeconfig` is `admin.conf`, a certificate only a CA rotation revokes; the API server has no OIDC | Accepted: one operator, LAN-only API | [Authorization](<https://homelab.wlkr.ch/architecture/security/index.md#authorization>) |
| **OpenBao speaks plain HTTP inside the cluster** | Secrets and tokens cross the pod network unencrypted; WireGuard covers node-to-node | Accepted: a certificate would sit in the unseal path | [OpenBao](<https://homelab.wlkr.ch/platform/openbao/index.md#at-a-glance>) |
| **OSDs are unencrypted, the Rook toolbox is on, Loki has no tenants** | A pulled disk is readable; the toolbox is a standing Ceph admin shell; any Grafana Viewer reads every log line, the audit log included | Accepted: disks stay on site, runbooks need the toolbox, one Grafana user | [Rook-Ceph](<https://homelab.wlkr.ch/platform/rook-ceph/index.md>), [Logging](<https://homelab.wlkr.ch/platform/logging/index.md>) |
| **SELinux is permissive on every node** | Flatcar's default: SELinux does not mediate a container escape, and Tetragon detects without confining | The denials are answered; enforce on one worker first | [Node hardening](<https://homelab.wlkr.ch/architecture/security/index.md#node-hardening>) |
| **Ceph's daemons run privileged** | `hostpathRequiresPrivileged`, Rook's switch for SELinux hosts: `container_t` may not write their hostPath data. A privileged container has every capability and no seccomp filter | Accepted until the paths carry a label | [Rook Ceph](<https://homelab.wlkr.ch/platform/rook-ceph/index.md#selinux>) |
| **The `infra` hostnames and the LAN address are in public DNS** | The infra names resolve publicly to a LAN address, so anyone can list them; they stay LAN-only | Accepted: no split DNS to run | [external-dns](<https://homelab.wlkr.ch/platform/external-dns/index.md>) |
| **Single region, site and rack** | Ceph replicates across nodes on one power feed and TrueNAS pulls the backups over the same LAN ([Off-cluster copy](<https://homelab.wlkr.ch/operations/backups/index.md#off-cluster-copy>)), so a site-level event takes everything | Honest limit of a homelab: a copy off the site | — |
| **No staging cluster** | A merge to `main` is a production deployment | The pull request checks and diff preview | [Contributing](<https://homelab.wlkr.ch/development/contributing/index.md>) |
| **The router and Authentik stand alone** | The router carries every Internet request and the BGP sessions; Authentik every UI login | LAN clients still reach the Gateways over L2 | [Cilium](<https://homelab.wlkr.ch/platform/cilium/index.md#configuration>), [When Authentik is down](<https://homelab.wlkr.ch/platform/authentik/index.md#when-authentik-is-down>) |
| **Backup copies hold plaintext Secrets and one all-powerful key** | Velero's resource backups keep Secrets as plain JSON, and the NAS's `offsite-reader` key owns the bucket, so a leak of either exposes every Secret or the backups themselves | Accepted; the NAS's snapshots outlive a deletion | [Repository password](<https://homelab.wlkr.ch/platform/velero/index.md#repository-password>), [Off-cluster reader](<https://homelab.wlkr.ch/platform/rook-ceph/index.md#off-cluster-reader>) |
