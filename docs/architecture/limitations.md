# Known Limitations

Things this cluster does not do. None is a bug; each is an accepted tradeoff
or work not yet done.

| Limitation | Consequence | Mitigation / plan | Where documented |
| --- | --- | --- | --- |
| **The API endpoint address is fixed at `kubeadm init`** | `controlPlaneEndpoint` is the kube-vip VIP, baked into the API server certificates, every node's kubeconfig and Cilium's `k8sServiceHost`; moving it regenerates certificates and rewrites kubeconfigs on every node | Choose it once, outside any DHCP range and the LoadBalancer pools; the next build [uses a name](../operations/control-plane-vip.md#endpoint-name) | [Choosing the address](../operations/control-plane-vip.md#choosing-the-address), [migrating in place](../operations/control-plane-vip.md#in-place) |
| **OpenBao needs an operator to unseal it** | Shamir seal, no auto-unseal: every restart seals each replica until the [threshold of key shares](../platform/openbao.md#at-a-glance) is supplied. Sealed, no `ExternalSecret` resolves and cert-manager cannot renew; the cluster looks healthy until a certificate expires | Check `bao status` after reboots; auto-unseal would add an external hard dependency | [Unsealing after a restart](../platform/openbao.md#unsealing-after-a-restart), [after any node reboot](../operations/nodes.md#after-any-node-reboot-unseal-openbao) |
| **Alerting reaches one mailbox** | One receiver, one mailbox, one SMTP provider. If mail is rejected or the password expires, alerts stop silently; `Watchdog` proves only as far as Alertmanager | A second receiver on a different transport; meanwhile, the routine health check | [Alerting](../platform/monitoring.md#alerting), [routine health check](../operations/index.md#routine-health-check) |
| **Automatic updates stop at patch releases** | Sysupdate is pinned to the Kubernetes major.minor in `ansible/inventory.yaml`; Kured reboots one node at a time and refuses while Ceph or etcd is unhealthy. A minor upgrade is manual. Kured blocks only on the alerts named in its config | By design | [Nodes are pinned to a minor series](../operations/upgrades.md#nodes-are-pinned-to-a-minor-series), [upgrading a minor deliberately](../operations/upgrades.md#upgrading-a-minor-version-deliberately), [Kured](../platform/kured.md) |
| **The `infra` AppProject is permissive** | The `infra` AppProject allows every kind in every namespace, so a platform `application.yaml` can deploy anything anywhere | Narrow the projects | [Security Posture](security.md#authorization) |
| **Reprovisioning needs the boot server on the segment** | Rebuilding a node needs `make serve` on a machine on the nodes' L2 segment, the external DHCP pointing at it and a power cycle; there is no remote rebuild | Only *re*provisioning: a running node reboots and rejoins without the boot server | [Boot & Bootstrap Process](boot-process.md#every-boot-after-the-first) |
| **The object store survives one host down, no more** | During every Kured reboot the RGW data pool, which holds the backups and Loki chunks, has no redundancy left, while `rbd-pool` still has some | Accepted: an existing pool's erasure profile cannot change, so it means a new pool and moving every bucket | [Object storage](../platform/rook-ceph.md#object-storage) |
| **Cluster admin is a client certificate, not OIDC** | `output/kubeconfig` is `admin.conf`, a certificate only a CA rotation revokes; the API server has no OIDC | Accepted: one operator, LAN-only API | [Authorization](security.md#authorization) |
| **OpenBao speaks plain HTTP inside the cluster** | Secrets and tokens cross the pod network unencrypted; WireGuard covers node-to-node | Accepted: a certificate would sit in the unseal path | [OpenBao](../platform/openbao.md#at-a-glance) |
| **OSDs are unencrypted, the Rook toolbox is on, Loki has no tenants** | A pulled disk is readable; the toolbox is a standing Ceph admin shell; any Grafana Viewer reads every log line, the audit log included | Accepted: disks stay on site, runbooks need the toolbox, one Grafana user | [Rook-Ceph](../platform/rook-ceph.md), [Logging](../platform/logging.md) |
| **SELinux is permissive on every node** | Flatcar's default: SELinux does not mediate a container escape, and Tetragon detects without confining | Try enforcing on one worker; watch Cilium, Tetragon, Rook and the CSI plugins | [Node hardening](security.md#node-hardening) |
| **The `infra` hostnames and the LAN address are in public DNS** | The infra names resolve publicly to a LAN address, so anyone can list them; they stay LAN-only | Accepted: no split DNS to run | [external-dns](../platform/external-dns.md) |
| **Single region, site and rack** | No failure domain larger than a node: Ceph replicates across nodes on one power feed, and TrueNAS pulls the backups over the same LAN ([Off-cluster copy](../operations/backups.md#off-cluster-copy)): a site-level event takes everything | Honest limit of a homelab: a copy off the site | — |
| **Backup copies hold plaintext Secrets and one all-powerful key** | Velero's resource backups are plain JSON in the bucket, Secrets included, and the NAS's `offsite-reader` key owns the bucket with a full `opMask`, so a leak of either exposes every Secret or lets its holder delete the live backups | Excluding Secrets would lose those nothing else regenerates (Argo CD, CloudNativePG, Rook, cert-manager); a read-only `opMask` would stop Rook setting the bucket policy with the owner's keys. The NAS's snapshots outlive a deletion | [Repository password](../platform/velero.md#repository-password), [Off-cluster reader](../platform/rook-ceph.md#off-cluster-reader) |
